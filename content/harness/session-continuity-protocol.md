# 세션 연속성 프로토콜

AI가 세션을 넘어 정보를 유지하고 서로 작업을 넘기는 방법이다. 이 문서는 2026-05-30에 `agent-memory-rules` + `agent-handoff-protocol`을 병합한 것이며([[change-history-ratchet|래칫]] 통합), 원본은 이력을 위해 보존된다. 개념적 다룸은 [[session-continuity-handoff]].

## Claude Code 메모리

로컬 에이전트 메모리 디렉터리에 저장된다. 네 종류: **user**(프로필, 숙련도, 반복 패턴), **feedback**(명시·암시 피드백을 규칙/이유/적용법 구조로), **project**(현재 상태, 열린 이슈, 결정 — 절대 날짜로 저장하지 않음), **reference**(자주 참조하는 외부 위치).

## 메모리에 저장 금지

키/토큰/비밀번호/자격증명; PII; 세션 한정 임시 상태; 코드 패턴/아키텍처(코드를 직접 읽음); git 히스토리 내용(`git log` 사용); 이미 CLAUDE.md에 있는 것; 핸드오프 상세(작업일지 사용).

## 작업일지 (모든 AI)

| AI | 경로 |
|---|---|
| Claude | `03_ai_notes/work-logs/claude/claude-work-diary.md` |
| Gemini | `03_ai_notes/work-logs/gemini/gemini-work-diary.md` |
| Codex | `03_ai_notes/work-logs/codex/codex-work-diary.md` |

- **시점:** 의미 있는 작업 후; 활성 작업 중에만 체크포인트 00:00 / 12:00 / 15:00 / 18:00 / 21:00(유휴 시간은 기록하지 않음). 메모리 규칙 원본은 이 시각 체크포인트가 명시적으로 허용되며 금지된 자율 자가 스케줄링 / cron 자가 기동과는 **다르다**고 분명히 한다.
- **규칙:** 새 파일을 만들지 않는다 — 기존 일지에 추가한다.
- **크기:** 체크포인트 1개 ≤2,000자; 긴 명령 출력 / 파일 목록 / 큰 diff / 전체 테스트 로그 금지(대신 별도 보고를 링크); 60,000자 또는 100 KB 전에 월별/주제별 롤오버 검토; 레거시 초과 일지는 보존(승인 없이 대량 분할/삭제/이동 금지).

## 컨텍스트 복원 (세션 시작)

1. 마지막 작업일지 항목 읽기 → "재개 지점"에서 시작. 2. 관련 파일 상태 확인. 3. Claude 메모리(피드백, 프로젝트 맥락) 확인. 4. 잔여 항목 체크리스트 확인.

## 핸드오프

발동 조건: 다른 AI/세션이 이어받음, 한 AI의 역할 밖으로 위임됨, 병렬 작업의 충돌 방지가 필요함, 작업이 여러 세션에 걸침. 핸드오프는 AI의 작업일지에 기록한다: 현재/다음 AI, 배경, 완료 항목, 잔여 항목(재개 지점), 관련 파일(볼트 상대), 핵심 결정(바꾸지 말 것), 알려진 이슈, 명시적 재개 지점. 역할 밖이고 더 적합한 AI가 분명히 있을 때 위임 가능; 결과가 즉시 필요하면 불가(AI 간 실시간 통신 없음).

## 동시 편집 잠금

한 파일당 한 AI; 시작 시 "편집 중 [파일]" 기록, 끝나면 해제; 다른 AI는 잠긴 파일에 읽기 전용. 충돌 시: 중단, 양쪽 버전을 사용자에게 보고, 사용자가 선택, 선택된 버전 통합.
