# 세션 연속성과 핸드오프

개별적으로 상태가 없는 AI 세션들을 하나의 연속된 멀티 에이전트 작업 흐름으로 바꾸는 관통 개념이다. [[session-continuity-protocol]]에서 구체화된다.

## 3개 영속 계층

1. **Claude 메모리**(`~/.claude/.../memory/`) — 휘발성, 도구별 profile/feedback/project/reference. 시크릿·PII·핸드오프 상세는 절대 담지 않는다.
2. **작업일지**(AI별, `03_ai_notes/work-logs/`) — 핸드오프 로그. 추가만 하고 재정리하지 않으며, 크기 상한(항목당 2,000자, 60,000자/100 KB 근처에서 롤오버).
3. **볼트**([[obsidian-vault]]) — 영속 장기 기억. 최종 문서는 어떤 세션과도 독립적으로 남는다.

세 계층은 휘발성과 신뢰도로 층을 이룬다: 메모리는 싸고 일시적, 일지는 잇는 장치, 볼트는 정본 진실이다.

## "재개 지점" 컨벤션

모든 핸드오프는 명시적 재개 지점을 기록한다 — "다음 AI는 [파일]에서 [작업]을 시작" — 그리고 완료/잔여 항목, 관련 파일, 바꾸면 안 되는 결정, 알려진 이슈를 함께 남긴다. 세션 시작 시 컨텍스트 복원은 이를 역순으로 한다: 마지막 일지 항목 읽기 → 파일 상태 확인 → 메모리 확인 → 잔여 체크리스트 확인.

## 동시성

한 파일에는 한 AI만, 락은 일지에 기록하고, 나머지는 읽기 전용. 충돌 시 작업을 멈추고 사용자에게 넘긴다. 이것이 같은 프로젝트를 [[ai-agent-roles|여러 에이전트]]가 서로 덮어쓰지 않고 작업하게 만드는 장치다.

## 체크포인트 vs 자가 기동 구분

고정 일지 체크포인트(00:00/12:00/15:00/18:00/21:00)는 **활성 작업 중에만** 허용되며, 금지된 자율 cron 자가 기동과는 명시적으로 다르다 — 메모리 규칙 원본이 짚는, 미묘하지만 중요한 구분이다.
