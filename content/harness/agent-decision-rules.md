# 에이전트 의사결정·에스컬레이션 규칙

작업 중 AI가 어떻게 판단하는지를 정한다. 기본 원칙은 **"확신이 없으면 묻는다"** 이지만, 동시에 명시적인 *자율 실행 구역*도 그어 둔다. 이 규칙을 관통하는 개념 모델은 [[agent-decision-escalation]]에 정리되어 있다.

## 자율 구역 (확인 없이 실행)

아래 조건이 **모두** 충족될 때만 묻지 않고 진행한다 — 되돌릴 수 있고(git/백업으로 복구 가능), 범위가 명확하고, 보안 위험이 없고, 데이터 손실이 없고, 외부 영향이 없을 때. 예: 새 볼트 문서 작성, 요청한 부분만 수정, 로컬 버그 수정, 볼트 검색·읽기.

## 에스컬레이션 트리거 (먼저 확인 필요)

- **A. 파괴적** — 파일 1개 이상 삭제, 내용 손실을 동반한 전체 덮어쓰기, 한 번에 50개 이상 파일 수정, DB 삭제/truncate.
- **B. 외부 영향** — git push / force push, 원격 배포, 외부 API 전송, 공개 저장소 업로드.
- **C. 보안/기밀** — 권한 상승(sudo/admin), 자격증명 변경, [[mark9|Mark9]] 기밀 데이터의 외부 반출.
- **D. 전문적 책임** — 의료/법률/금융 판단의 최종 확정.
- **E. 방향 불명확** — 결과가 크게 갈리는 두 가지 해석이 있거나, 기존 작업과 충돌하는 요청.

## 충돌 우선순위 (7단계)

1. 사용자 직접 지시 (현재 세션)
2. [[ai-master-constitution]] (보안·무결성)
3. 하네스 파일 (`00_Harness/`)
4. 공유 AI 설정 허브
5. AI별 전역 설정 (`%USERPROFILE%\.claude\CLAUDE.md` 등)
6. 프로젝트 로컬 설정
7. 기존 볼트 관례

언제나 **더 엄격한 규칙이 이긴다.**

## 모호한 요청 처리

가장 단순하게 해석한다 → 안전하고 되돌릴 수 있으면 가정을 밝히고 진행한다 → 그렇지 않으면 확인한다. 완료 후 적용한 가정을 보고한다. 확인 형식: "[요청]을 [A]로 이해했습니다. [B]를 뜻하셨나요? 확인이 없으면 [A]로 진행하겠습니다."

## Mark9 기술 선택

[[mark9|Mark9]] 개발은 Rust를 먼저 시도한다. 중대한 제약(Rust 미지원, 생태계 부재, 학습곡선 과도)이 있으면 대안을 제안하고 Rust를 쓰지 않은 이유를 기록한다. 실험·UI·AI/ML·빠른 검증에는 Python/TypeScript/React를 허용한다.

## 파일 위치 결정

최종 문서 → `볼트 루트\`; 코드/실험/임시물 → `프로젝트 루트\` 또는 지정 폴더; 보고용 산출물 → 볼트 표준 위치; 임시 파일 → 작업 후 정리.
