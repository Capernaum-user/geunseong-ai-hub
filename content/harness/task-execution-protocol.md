# 작업 실행 프로토콜

AI가 처음부터 끝까지 따르는 표준 절차다.

## 세션 부팅 순서

1. 현재 사용자 요청 + 활성 시스템 지시 확인
2. 전역 설정 로드(CLAUDE.md 등 — 자동)
3. 공유 AI 설정 허브 확인
4. 관련 하네스 파일 참조
5. 볼트에서 관련 기존 문서 검색
6. 관련도 높은 문서 읽기
7. 작업일지의 이전 세션 재개 지점 확인
8. 작업 범위 + 저장 위치 결정

## 실행 흐름

- **1단계 — 요청 분석:** 무엇을 만들/고칠/조사할지, 범위가 명확한지, [[agent-decision-rules|에스컬레이션 트리거]]에 걸리는지, 누구의 역할인지([[ai-agent-roles]]).
- **2단계 — 볼트 사전 검색(RAG 우선):** 볼트에는 시맨틱 RAG 인덱스가 있다. 파일명-키워드 검색보다 먼저 쓴다. `python 볼트 루트\.rag\query.py "키워드"`(플래그: `--top`, `--project`, `--type`, `--json`). `similarity >= 0.5`인 문서를 먼저 읽는다. 40 KB 초과 파일: 헤딩 / `rg` / 라인 윈도우로 좁힌 뒤 통째로 읽는다.
- **3단계 — 실행:** 문서 작업(파일명 → 위치 → 프론트매터 → 내용 → [[file-operations-rules|크기 예산]] → 정당할 때만 내부 링크); 코드 작업(기존 읽기 → 최소 변경 → 요청 범위만 구현 → 문법/타입/보안 자가검증 → 크기 점검 → 변경 설명 준비); 리서치(기존 확인 → 수집 → 출처 기록 → 정제 → 볼트 저장).
- **4단계 — 자가검증 + RAG 갱신:** 해당 [[task-completion-standards|완료 체크리스트]] 통과; 보안 스캔(키/PII 없음); 파일 크기 점검; **필수:** 볼트 파일을 생성/수정/삭제했다면 보고 전 `python 볼트 루트\.rag\ingest.py` 실행.
- **5단계 — 완료 보고:** 처리 항목 / 미처리 항목 + 이유 / 에러 & 주의 / 참조한 볼트 문서.
- **6단계 — 작업일지 갱신**(의미 있는 작업).

## 도구 우선순위 (Claude)

| 목적 | 1순위 | 2순위 | 금지 |
|---|---|---|---|
| 볼트 시맨틱 검색 | `python .rag/query.py` | Grep | — |
| 파일 읽기 | Read | — | `cat`(Bash) |
| 파일 쓰기 | Write/Edit | — | `echo >`(Bash) |
| 파일명 패턴 | Glob, Grep | — | 맨 `find` |
| 볼트 작업 | `mcp__obsidian__*` | Read/Write | — |
| 시스템 정보 | PowerShell | Bash | — |

## 병렬성 & 중단

독립 작업은 병렬로 실행(다중 파일 읽기, 독립 생성, 다중 검색); 순서/의존 단계와 한 파일에 대한 동시 쓰기는 절대 병렬화하지 않는다. 중단 시: 완료 항목 + 명확한 재개 지점 + 잔여 목록을 작업일지에 기록; 재시작 시 파일 상태를 확인한 뒤 그 지점부터 재개.
