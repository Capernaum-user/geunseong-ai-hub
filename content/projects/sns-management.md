# SNS 관리 시스템 설계 — 데이터 모델과 기능 기획

여러 SNS 채널을 하나의 업무 시스템에서 작성·예약·발행·승인·분석하는 운영 플랫폼을, 코드를 쓰기 전에 데이터 모델과 기능부터 설계한 케이스 스터디입니다.

## 배경과 문제

채널마다 따로 로그인해 같은 글을 올리고, 예약·승인·발행 이력이 흩어지는 반복이 문제였습니다. 이를 시스템으로 묶으려면 "어떤 화면을 만드나"보다 "데이터를 어떻게 나누나"가 먼저였습니다.

## 접근과 설계

핵심은 ERD 설계였습니다. company → workspace → social account → post의 계층으로 잡고, 다음 원칙을 두었습니다.

- **멀티테넌시**: 모든 업무 데이터에 workspace 단위 격리를 적용해 브랜드·고객사가 섞이지 않게 한다.
- **공통/플랫폼 분리**: 공통 post와 플랫폼별 post version을 나눠, 채널별 규격 차이를 흡수한다.
- **발행 안정성**: 발행 job과 발행 결과를 분리하고 멱등성을 둬, 중복·실패를 추적한다.
- **보안 우선**: OAuth 토큰은 별도 테이블에 암호문으로만 보관하고, 외부 API 원문은 마스킹 후 저장한다.

플랫폼별 차이는 JSON 페이로드로 확장하되 검색 키는 별도 컬럼으로 분리해, 유연성과 조회 성능을 함께 챙겼습니다.

## 상태와 배운 점

이 설계 기획이 [[products/channeldock|ChannelDock]] 제품의 토대가 되었습니다. 가장 큰 배움은 통합 발행의 난점이 화면이 아니라 데이터 경계와 발행 상태 관리에 있다는 점이었습니다.
