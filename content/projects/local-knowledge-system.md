# Local Knowledge System — 개인 로컬 지식 시스템 프레임워크

> 도구를 깔기 전에 규칙부터 쓴다. 작게 시작하고, 원본을 보존하고, 단계마다 검증한다.

## 배경 — 문제

개인 지식베이스를 AI가 읽고 쓰는 시스템으로 키우려 하면, 의미 검색·메타데이터 DB·백업·외부 동기화 같은 조각을 한꺼번에 붙이고 싶어진다. 그 결과는 보통 원본이 흐트러지고, 비밀값이 문서에 새고, 무엇이 진실원인지 모르게 되는 상태다.

## 접근 — Stage 0 프레임워크

그래서 코드를 먼저 짜지 않고 **운영 원칙(Stage 0)** 부터 확정하는 방식을 택했다. 시스템 사고로 전체 단계를 먼저 지도화하고, 지금 단계만 실행한다.

- 한 번에 다 만들지 않고, 실제 파일을 만들기 전 생성될 폴더·파일 목록을 먼저 제시한다.
- 마크다운 금고를 단일 진실원으로 두고, 코드·런타임은 금고 밖에서 돌린다.
- 의미 검색 인덱스에는 원문을 복제하지 않고 청크와 메타데이터만 담는다.
- 비밀값은 문서가 아니라 환경변수·안전 저장소로만 다룬다.

로드맵은 구조 점검 → 메타데이터 설계 → 로컬 의미 검색 PoC → 자동정리 → 백업 → 외부 동기화로 단계를 끊어, 각 단계의 산출물과 검증 기준을 미리 정해 둔다.

## 상태 / 배운 점

원칙과 기본 경로를 확정한 초기 단계다. "무엇을 안 할지"를 먼저 적어 두니 다음 단계의 범위가 저절로 좁아졌다. 도구 선택보다 진실원·보안·검증 순서를 정하는 일이 시스템의 성격을 더 크게 좌우한다는 걸 확인한 사례다.
